# Repository Guidelines

## Project Overview

Supabase CLI is a pnpm/Nx monorepo for developing, testing, packaging, and distributing the `supabase` command. The primary CLI package lives in `apps/cli` and uses Bun/TypeScript plus Effect; the legacy Go CLI remains in `apps/cli-go` for sidecar compatibility, local-stack orchestration seams, and this fork's dependency-replacement work.

## Architecture & Data Flow

- **CLI entry flow:** published shim `apps/cli/src/shared/cli/bin.ts` resolves a platform binary package or `SUPABASE_CLI_BINARY_OVERRIDE`; TypeScript dev entry points are `apps/cli/src/next/main.ts` and `apps/cli/src/legacy/main.ts`.
- **TypeScript CLI layers:** `apps/cli/src/{next,legacy}` contain command shells; shared runtime/services/output/auth/telemetry live under `apps/cli/src/shared`; tests mock services with Effect layers.
- **Go CLI layers:** `apps/cli-go/main.go` calls Cobra root `cmd.Execute()`; command wrappers in `cmd/` delegate to `internal/`; shared Go libraries live in the nested module `apps/cli-go/pkg`.
- **TS/Go bridge seams:** Go exposes hidden machine-readable seams used by TS-native commands: `db __shadow`, `db __db-bootstrap`, and `db schema declarative __catalog`. Keep stdout contracts stable.
- **Local stack/data flow:** config comes from `packages/config` and Go `pkg/config`; `packages/stack` and `packages/process-compose` orchestrate local services; Docker image tags are sourced from `apps/cli-go/pkg/config/templates/Dockerfile`.
- **API clients:** `packages/api` is the typed Supabase Management API client for TS; `apps/cli-go/pkg/api/*.gen.go` is generated by `oapi-codegen` for Go.
- **Fork-specific dependency flow:** this fork replaces heavy upstream deps with stubs in `apps/cli-go/go.mod`: `go-ethereum => ./internal/go-ethereum-stub` and `containers/common => ./internal/containers-common-stub`. Preserve these across upstream syncs.

## Development Commands

Run commands from the repo root unless noted.

| Command | Purpose |
| --- | --- |

| `pnpm install` | Install workspace dependencies. |

## Code Conventions & Common Patterns

- **Package manager:** use `pnpm`, not `npm run` or `bun run`, except scripts that explicitly invoke `bun` in `package.json`.
- **Runtime style:** TS workspaces target Bun and ESM (`type: module`); Go code follows standard Cobra/internal/pkg layout.
- **Effect patterns:** prefer Effect services/layers in TS command logic. In tests, stateful mocks return `{ layer, state }`; assert accumulated state rather than internal call ordering.
- **Errors as values:** model expected failures in typed result/effect channels; avoid exceptions as control flow. Fail fast for programmer errors.
- **No type silencing:** do not use `as` casts to bury TypeScript errors in production code. Fix the type boundary.
- **Generated code:** do not hand-edit generated API/config outputs. Regenerate with the owning package script or `go generate` where documented.
- **CLI command tests:** prefer integration tests for command behavior: parsing, output, errors, feature matrices, and service interactions. Keep e2e scarce.
- **Output assertions:** assert user-visible behavior and resulting state; avoid testing incidental internal call order.
- **Fork stubs:** never remove the Go `replace` directives for `go-ethereum` and `containers/common`; these are the point of the fork, not debris.
- **Refactors:** internal backward compatibility is not sacred. Delete obsolete shims/helpers when ownership moves, but update tests/docs in the same change.

## Runtime/Tooling Preferences

- Use **mise 2026.7.0+** when possible: `mise trust && mise install`.
- Version sources:
  - Node: `package.json` `devEngines.runtime.version` (`24`)
  - pnpm: `package.json` `packageManager` (`pnpm@11.4.0`)
  - Bun: `.bun-version` (`1.3.13`)
  - Go/golangci-lint: `mise.toml`
- Nx inferred targets are real targets. Discover with `nx show project <name>` or `nx show projects`; do not infer from `package.json` alone.
- `.repos/effect/` is the preferred reference for Effect v4 APIs. Run `pnpm repos:install` after a fresh clone before deep Effect work.
- Local release testing uses Verdaccio: `pnpm local-registry` in one terminal, then `pnpm cli-release --next` or `--legacy` in another.
- PR titles must follow conventional commits (`fix(cli): ...`, `test(cli): ...`). Use non-releasing types (`chore`, `docs`, `test`, `ci`) for maintenance.
- Do not add validation/test-plan boilerplate to PR descriptions; CI is the validation source of truth.

### Updating this fork, rebuilding, and installing the Arch package

The working checkout usually lives inside an AUR/package directory:

- fork checkout: `/home/svnbjrn/dev/supabase-git/supabase-cli`
- package root: `/home/svnbjrn/dev/supabase-git`
- PKGBUILD source branch: `develop`

**Mechanical path:** run `/home/svnbjrn/dev/supabase-git/update-fork.sh`. It performs every step below (fetch, merge, fork-owned-path restoration, go.mod/go.sum reconciliation, build+test gate) and stops before commit/push/install for review. The manual steps are documented here so the rationale behind each is traceable and so a novel conflict (the script exits nonzero and tells you which paths) can be resolved by hand.

Process:

```sh
cd /home/svnbjrn/dev/supabase-git/supabase-cli
git fetch upstream-real --tags
git checkout develop
git merge upstream-real/develop --no-edit
```

Conflict rules — apply ALL of these after every merge, not just the ones git flags as conflicted. Several of these paths get **silently deleted with no conflict marker at all** when upstream has removed the same path and the fork's copy wasn't independently touched in that merge — git resolves that as a clean delete. The only reliable defense is restoring unconditionally, which is exactly what `update-fork.sh` does.

1. **`apps/cli-go/go.mod` / `go.sum`** — take upstream's module updates, then re-add the two fork-specific replacements:
   ```go
   replace github.com/ethereum/go-ethereum => ./internal/go-ethereum-stub
   replace github.com/containers/common => ./internal/containers-common-stub
   ```
   Upstream-owned replacements such as `github.com/supabase/cli/pkg => ./pkg` and `github.com/fsnotify/fsevents => ./fsevents` should survive normally.
2. **`apps/cli-go/internal/start/`, `apps/cli-go/cmd/start.go`, `apps/cli-go/cmd/start_test.go`** — permanently fork-owned (see `FORK_MAINTENANCE.md` item 3). Upstream deleted `internal/start` outright and reduced `cmd/start.go` to a stub that always errors. Always restore all three paths from the pre-merge `develop` HEAD after merging, unconditionally:
   ```sh
   git checkout <pre-merge-HEAD> -- apps/cli-go/internal/start apps/cli-go/cmd/start.go apps/cli-go/cmd/start_test.go
   git add apps/cli-go/internal/start apps/cli-go/cmd/start.go apps/cli-go/cmd/start_test.go
   ```
3. **`.github/dependabot.yml`** — the fork deletes this file; upstream edits it almost every sync, so it reappears via merge. Always re-delete after merging:
   ```sh
   git rm -f --ignore-unmatch .github/dependabot.yml
   ```
4. **`apps/cli-go/internal/utils/docker.go`** — only `NewDocker` and `loadRegistryAuth` are allowed to diverge from upstream, and they live in `apps/cli-go/internal/utils/docker_fork.go`, not in `docker.go` itself. `docker.go` should always be able to take upstream's version wholesale. If a merge conflicts inside `docker.go` outside of a call site referencing `docker_fork.go`'s functions, something has drifted from this convention — investigate rather than blindly keeping either side.
5. Run tidy with the system resolver if DNS through pure Go times out:
   ```sh
   cd apps/cli-go
   CGO_ENABLED=1 GODEBUG=netdns=cgo GOSUMDB=off GOPROXY=https://proxy.golang.org,direct go mod tidy
   ```
6. Verify the Go fork before packaging:
   ```sh
   GOSUMDB=off CGO_ENABLED=0 go build -mod=readonly ./...
   go test -short ./internal/sandbox/... ./internal/start/... ./internal/status/... ./internal/utils/... ./cmd/...
   ```
7. Build and install the package:
   ```sh
   cd /home/svnbjrn/dev/supabase-git
   makepkg -sf --noconfirm
   sudo pacman -U --noconfirm supabase-git-<pkgver>-1-x86_64.pkg.tar.zst
   supabase --version
   pacman -Q supabase-git
   ```

Notes:

- `makepkg` updates `pkgver` from git tags, excluding prerelease tags. Latest stable tag plus commits becomes e.g. `2.109.1.develop.r61.g0733dcaa`.
- PKGBUILD normally fetches `origin/develop`. A local unpushed build only packages your checkout when makepkg's VCS source cache is already `/home/svnbjrn/dev/supabase-git/supabase-cli` at the intended `HEAD`; a fresh source cache can silently build the older remote commit.
- Before installing, compare the intended checkout SHA to the built package version/source SHA:
  ```sh
  git -C /home/svnbjrn/dev/supabase-git/supabase-cli rev-parse --short HEAD
  bsdtar -xOf supabase-git-<pkgver>-1-x86_64.pkg.tar.zst .PKGINFO | grep '^pkgver = '
  ```
  The package `pkgver` must contain the same `g<sha>` suffix when building an ahead-of-remote checkout.
- Do **not** push `develop` unless the user explicitly asks to publish the fork. If publishing is requested, use normal `git push origin develop`; never force-push without explicit approval.
- `feature/full-sandbox` is not the packaged branch unless explicitly requested.

## Testing & QA

- **Default gate for changed TS workspaces:** run unit + integration for the workspace you touched, then the relevant check target.
  ```sh
  cd apps/cli
  pnpm test:core
  pnpm check:all
  ```
- **Root core tests:** `pnpm test:core` runs `nx run-many -t test:unit test:integration --coverage.enabled`.
- **E2E policy:** do not automatically run the full e2e suite. Run targeted e2e files only when the command boundary requires real subprocess/runtime coverage or the user asks.
- **Vitest projects:** local Nx plugin reads `vitest.config.ts` and creates `test:unit`, `test:integration`, `test:e2e`, and `test:live` targets where configured.
- **`apps/cli` tests:** use `@effect/vitest`, `it.live`, and helpers in `apps/cli/tests/helpers/`; e2e uses `runSupabase()` with isolated `SUPABASE_HOME`.
- **`apps/cli-e2e`:** replay mode is default and deterministic. Record mode (`RECORD=true`, usually Go harness) talks to staging and writes fixtures under `fixtures/recorded/` and `fixtures/scenarios/`; review placeholders so no secrets/project refs are committed.
- **Live tests:** gated by env (`SUPABASE_ACCESS_TOKEN`, live project refs/URLs) and are not a normal PR feedback loop.
- **Go tests:** `apps/cli-go` uses standard `*_test.go`, testify, gock, afero, pgtest, and Docker mocks. CI uses gotestsum/race/coverage plus golangci-lint and codegen drift checks.
- **CI map:** `.github/workflows/test.yml` is the main PR gate; `.github/workflows/cli-go-ci.yml` covers Go; `.github/workflows/live-e2e.yml` is scheduled/non-blocking; release workflows run smoke/install-channel checks.
- If you run a workspace check command, you own its failures until resolved or explicitly documented as an external blocker. Do not hand-wave failures as “probably pre-existing.”
